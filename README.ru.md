# Как один Archer AX80 EU получил новую загрузочную цепочку

[English version](README.md)

Хотелось, чтобы на роутере помещался нужный набор программ и чтобы для хранения настроек не требовалась USB-флешка. На **TP-Link Archer AX80 EU v1.0** уже был OpenWrt рядом со штатной системой. Но заводская схема с двумя слотами оставляла OpenWrt заметно меньше места, чем можно было ожидать от NAND на 128 МиБ.

Здесь собрана история перехода на другую загрузочную цепочку и единый UBI: что пробовали, где ошиблись, какие проверки помогли и что в итоге заработало. **Это один случай, а не инструкция.** Работа прошла без подключённого UART-адаптера. Владелец принял риск для этого устройства; успех не делает такой путь безопасным для остальных. Неудачная запись загрузчика может оставить кирпич без сетевого восстановления, а потеря заводской калибровки — работающую систему с неисправным Wi-Fi.

## Что происходило

1. **Большой образ не загрузился.** 7 октября после записи кастомного образа около 50,4 МБ роутер вернулся в штатную систему. У прежнего слота OpenWrt было примерно 44 МБ реальной ёмкости. Вероятная причина — размер, альтернативная — счётчик загрузок стокового U-Boot. Корневую причину не доказали. Успешный `sysupgrade -T` не был проверкой вместимости.
2. **Сначала сохранили исходное состояние.** На штатной 1.1.2 получили временный административный доступ через включение telnet. Семь видимых разделов прочитали дважды; каждый файл проверили по размеру и SHA256. Отдельно сверили заводские файлы. Это было 123 МиБ данных разделов, без последних 5 МиБ NAND и без OOB.
3. **Диагностика завела в тупик.** Старый том kernel увеличили, записали диагностический FIT и загрузились в RAM. Удалось прочитать весь NAND по разделам, но все MTD были только для чтения. Проверенного kexec не было, а выход заранее не подготовили. Пока сохранялся заводской загрузчик, пришлось использовать его recovery, вернуться в сток, затем через официальный initramfs перейти в отдельный записываемый migration initramfs.
4. **Новую цепочку проверяли на компьютере.** В U-Boot исправили выбор redundant env и обработку ошибок TFTP/записи. Проверили формат FIT, геометрию UBI, размеры и хеши payload, CRC окружения. Две копии env заполнили заранее: первый старт должен был выбрать recovery, без зависимости от интерактивной инициализации меню.
5. **Запись разделили на три фазы.** Сначала factory из собственных данных роутера, затем единый UBI, затем BL2. После каждой фазы прочитали результат обратно и проверили. Последовательность не атомарна: обрыв питания между фазами всё равно мог лишить устройство загрузки.
6. **Запустили recovery, затем основную систему.** Первая новая загрузка дала RAM recovery. После отдельного изменения env основная система загрузилась из внутренней NAND. Обычный повторный ребут сохранил настройки. USB extroot больше не требовался.

Подробности и исторические команды с объяснениями — в [docs/README.md](docs/README.md). Команды записи приведены как свидетельства работы; приватные пути убраны. Готового установщика здесь нет.

## Чем закончилось

На установленной системе наблюдались board `tplink,archer-ax80-v1-eu-ubi`, OpenWrt SNAPSHOT `r0-d4ebffe5`, Linux `6.18.26`, SquashFS `/rom` и внутренний UBIFS overlay с записью. В UBI шесть томов: `fip`, `ubootenv`, `ubootenv2`, `fit`, `recovery`, `rootfs_data`. На позднем снимке аудита свободно около 27,9 МиБ overlay. Factory совпал с подготовленным приватным бэкапом; это проверка сохранности, а не тест характеристик радио.

Работал доступ по Ethernet; сам роутер выполнял DNS/HTTPS-запросы. Обе точки Wi-Fi были включены к итоговому аудиту. Физическое нажатие WPS открыло PBC на обеих на 120 секунд, но сопряжение клиента не проверяли. Проверили часть LED и программных обработчиков кнопок. В сохранённом снимке NAND не было зарегистрированных bad blocks или ошибок ECC.

## Не путать три результата

| Набор | Что подтверждено |
| --- | --- |
| Кастомная установка 8–9 октября | Recovery, production и обычный повторный ребут на одном устройстве с локальными изменениями |
| Поздняя кастомная пересборка | Только офлайн-проверки; production больше старого fit, recovery имеет запас всего 73 728 байт; не готова к установке |
| Перенос PR 13 октября | Собраны оба EU-профиля и проверены шесть артефактов; на устройстве не запускались; redundant env в чистом загрузчике не включён |

При переносе двух upstream-коммитов сохранили их авторство и поправили только конфликтующие списки плат. Первая сборка упала из-за Windows-путей со скобками в WSL `PATH`; повтор с Linux-only `PATH` прошёл. Пять старых локальных патчей в чистую сборку не включали. Отдельный review-fixup проверили по исходникам, но не собирали; он не выдаётся за использованный код миграции.

## Что ещё не доказано

Физический вход в recovery, восстановление по UART и возврат новой разметки в сток, отказ загрузки, WPS-сопряжение, каждый Ethernet-порт, скорость Wi-Fi, клиентские VPN/DNS/IPv6 и длительная нагрузка не проверены. Заводской dual-slot fallback утрачен. Выбор TFTP кнопкой Reset выведен из сохранённого env, а не испытан. После передачи управления зависшему ядру U-Boot не гарантирует автоматический переход в recovery.
