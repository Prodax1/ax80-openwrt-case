# 6. От аппаратного кейса к чистому upstream-переносу

13 октября два коммита PR #21640 перенесли на `main` срез `3fba6794e24542494853454cdaf52595dab4a37b`. Первый применился автоматически. Во втором вручную разрешили два списка `platform.sh`: сохранили все новые платы main и добавили AX80 EU UBI. Это не изменение алгоритма updater. Новая вершина — `c45a44104bed327868be619a0d4e621952b05e1f`; исходная — `d4ebffe538ab94d9b5a604f4bba28325f38ed3d8`.

Пять прежних локальных патчей и старый files overlay не переносили. Это отдельный эксперимент: убедиться, что исходная поддержка компилируется на выбранной новой базе. Авторство upstream сохранено; текущий статус PR не выводится из успешной сборки.

Исторические команды в отдельном чистом Linux-дереве:

```sh
make defconfig
./scripts/diffconfig.sh
make -j8 download V=s
make -j8 V=s
```

`defconfig` разрешает зависимости Kconfig, `diffconfig.sh` извлекает выбранные отличия, `download` получает исходные архивы, последний make компилирует. Использовали внешний GCC 14.3.0/musl 1.2.5, а не дефолтный GCC 14.4.0 этой main. Точное итоговое `.config` и diffconfig приложены; external-toolchain paths обезличены и должны быть сопоставлены реальному окружению, иначе воспроизведения не получится.

Первая сборка отказала в рецепте U-Boot с `syntax error near unexpected token '('`: Windows PATH со скобками попал в shell-подстановку. Исправили окружение, а не исходные коммиты:

```sh
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
make -j8 V=s
```

Итоговый make завершился с кодом 0. Остались compiler warnings и `Error 1 (ignored)` от намеренно игнорируемого rmdir TF-A; они не равны отказу make. При дозапуске выяснили, что сборка уже завершилась, хотя отчёт ещё не обновили; повторно компилировать не стали. Независимый verifier сверил артефакты и конфиг, exit 0.

Два EU-профиля дали шесть образов: обычные initramfs/sysupgrade, UBI BL2/FIP/recovery/sysupgrade. SHA256/размеры совпали с Linux-выходом и profiles.json. Для UBI FIT проверили CRC32/SHA1 payloads, DTB compatible, config-1. FIP payloads сверили с BL31/U-Boot выходами; BL2 — со staged preloader. Полную повторную проверку внутренних payload-хешей обычного EU initramfs не делали. Это целостность и структура, а не hardware boot и не криптографическая подпись.

Новая база меняла Linux 6.18.26 → 6.18.55, U-Boot 2026.01 → 2026.07 и TF-A. Маленький размер объясняется базовыми пакетами вместо кастомного набора. Сравнение per-device rootfs дало 127 пакетов обычного профиля и 120 UBI; общий rootfs до device additions имел другое число и не доказывает отсутствие радио в конечном образе.

В скомпилированном чистом U-Boot `CONFIG_ENV_REDUNDANT` остаётся выключен; второго env volume в итоговом Kconfig нет. Поэтому чистый loader не объявляется проверенной заменой custom loader с двумя env. Отдельный review-fixup проверяли по исходникам, но не собирали; он исключён из каталога использованных патчей. Размер и результат make не дают разрешения на запись устройств.
